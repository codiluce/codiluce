The compiler has an owned heap boundary

The default pipeline uses a dedicated child with 1,024 MiB old space, 16 MiB semi-space and 64 MiB maximum request and response frames. Actual successful compiled probes report a 1,072 MiB V8 heap ceiling. These settings follow the Node 22 old-space option and semi-space accounting. They bound JavaScript heap use; native allocations, Buffers and total physical RSS need separate accounting.

Each connected component retains separate project programs through declaration, framework, HTTP and reference passes. No admitted original is dropped to satisfy the heap limit. Component programs retire at their existing boundary; the child and its optional parser descendants retire before the parent accepts a successful graph patch. Embedded inputs transfer plain recipes and original spans, then reread originals through the indexed source/hash boundary.

HTTP observations reconnect to their caller’s exact effect position. Cache hits and callbacks remain visible to the parent after successful worker completion. Heap failure, malformed replies, failed exit codes or incompatible graph patches reject the pass without partial parent graph replay. Parent exit and SIGTERM controls terminate outstanding owned work. Parent registry mutation cannot install executable hooks in the child; pack authors ship reviewed code in the worker’s module closure.
