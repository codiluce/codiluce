Languages, imports and framework profiles

Capabilities and versionsPack-author guideImplementation roadmap

Choose a source-analysis profile for the language and framework in your repository. These are bounded static capabilities: original declarations, imports, registrations and evidence are analyzed without building or running the target application.

The result for each file is the authority. Read entity.metadata.analysis.features for structure, imports, references, framework, effects and guards. supported qualifies that feature's documented profile; partial preserves useful facts plus gaps; unsupported has no active contract; disabled records exclusion or inactive inputs; failed records an attempted parse/read/analysis failure. Recognizing a file extension alone never creates semantic coverage.

Framework version ranges must select one reviewed contract through a proven dependency/namespace. A package name, local lookalike, broad version range or missing target input does not certify runtime behavior. Unknown routes remain constrained competitors instead of disappearing from matching.

Limits and release status

Indexed source boundary
Fresh reads require indexed, analyzable, unchanged originals and recorded scan availability; source memos preserve already validated scan inputs. Replay boundaries use explicit fresh validation. The configured maxFileBytes remains the per-original input limit.
Source memo
32 MiB of conservative UTF-16 text/key payload, at most 4,096 entries per instance; streaming consumers retire originals. This is an ownership limit, not physical RSS.
Native generations
At most six primary/auxiliary grammars or 16 MiB cumulative original UTF-8 input before retiring a generation and awaiting exit. One allowed larger original remains analyzable.
PHP provider
32 MiB accounted representation / 4,096 resident units; private ephemeral snapshots capped at 256 MiB / 4,096 entries. Six admitted reads share 16 MiB of original input; one allowed larger original runs alone. Consumer-tree retirement is under final qualification in the roadmap.
Persistent analysis cache
Two versions per unit, 256 MiB compressed overall, 64 MiB decoded per entry. Missing, corrupt, invalid or oversized entries fall back to source. Cache hits validate required source inputs and semantic services restore the identities they need.
Qualification
Conformance, installed-package, mixed-stack and history reports are linked from the roadmap. Recorded Linux/Windows/macOS target inputs qualify source selection; they do not prove native OS execution. Native Windows/macOS release qualification, wider production histories and remaining semantic/compiler/WASM memory budgets are open.

Node >=22.12.0 is the package engine requirement. No target PHP/Composer, Python application, Ruby/Liquid, JVM/.NET, Go/Rust compiler, build hook or framework dependency is executed by source qualification.
