What runs

.github/workflows/native-compatibility.yml runs on pull requests, main-branch pushes and manual dispatch. Six independent jobs use real Ubuntu, Windows and macOS runners, each with the minimum supported Node 22.12.0 and the selected Node 24 line. Each receipt records the resolved Node version, architecture, OS type/release, Git version, checked-out commit and SHA-256 inventory of exact tracked source bytes. Runner-image labels and the Node 24 patch may change; the recorded host, rather than its label, is the evidence.

Run a clean checkout locally

Use a supported Node installation and Git. The runner resolves npm's JavaScript CLI beside Node, so command execution needs no platform shell or Windows npm.cmd invocation.

node scripts/qualify-native-release.mjs --install --output test-results/native-release

# Inspect the exact command plan without executing checks:
node scripts/qualify-native-release.mjs --install --plan

Every output directory must be new. For a repeat, choose a different directory and retain the old observations. The runner writes receipt.json, a browser-accessible index.html and complete per-check logs. Open the HTML directly in a browser, or serve the downloaded artifact directory with a static HTTP server.

Interpret the result

A pass requires every selected check to finish with exit code zero and no signal or spawn failure, a clean checkout and identical before/after source bytes and commit. The runner writes progress before starting each child, waits for its completion and closes the log descriptor before hashing evidence. Nonzero exits, missing executables, interrupted jobs, unavailable source identity, dirty or changed sources and dependency skips cannot qualify a host. A failed validation check does not discard later independent checks; a failed dependency installation records prerequisite skips.

The matrix keeps fail-fast: false. Every job attempts artifact upload even after failure, with a distinct host/Node/attempt name and a missing-artifact error. Download each job's native-release artifact and open index.html; receipt.json and SHA-256 log checksums retain machine-readable evidence. All configured jobs must qualify before the native release gate can be closed. This matrix does not establish other architectures, runtime versions, production performance or wider original-source accuracy.

Workflow inputs

Official actions are pinned to immutable commits, with read-only repository permissions and no persisted checkout credentials. The action usage and artifact behavior follow checkout v7.0.1, setup-node v7.1.0 and upload-artifact v7.0.2. Updates require reviewing their real source and retaining this qualification contract.
