Completed change

Workers encode the complete response before stamping completion. A small private completion frame precedes the response bytes. The parent accepts a completed source only when the worker timestamp is inside the original ten-second job deadline, including startup, input delivery, parsing, extraction and serialization. Parent analysis can delay response handling without turning that completed job into a timeout.

Completed-response delivery has a separate finite ten-second parent-idle allowance. Actual late source completions, missing payloads, invalid clocks, inconsistent lengths and malformed frames still fail. Failed processes exit before replacements dispatch. Termination keeps IPC intact while decoded frames drain. Transport metadata stays outside every graph fact.

The 17 cases include small and 2 MiB responses under parent stalls, a genuinely late worker while the parent misses its timer, a stall during payload delivery, missing responses and five malformed-frame profiles. Both initial busy-parent cases fail on the prior transport. Retained intermediate channel failures were corrected; all final checks pass. Host-clock implementation was reviewed in the pinned Node source; parent-idle handling follows the Node API contract. Source review does not qualify native Windows/macOS execution.
