Bounds and failure behavior

Per-file admission limits are 65,536 distinct entries, 8 MiB of exact UTF-8 JSON table payload, 16 MiB of total ordered-reference JSON payload and 65,536 references per proof. Each admission is atomic. Snapshots preserve public JSON fields without retaining original mutable objects; cached identities revalidate current primitive fields. Encoding lookup and identity caches retire at file completion.

A failed admission retains that row and later rows as complete original inline evidence, marks reference coverage failed and records rust-evidence-retention-budget. Such fallback cannot qualify this compact storage profile. A configured table limit smaller than the two-byte empty JSON table is rejected before admission. The bounds cover table/reference payloads; they do not cap the whole graph, decoded objects or physical RSS. Symbol producer and router cache dependencies invalidate earlier proofs on upgrade.
