Original bytes, bounded inputs

The runner reads Git object bytes directly, checks their full SHA-1 or SHA-256 Git blob identity, computes original-byte SHA-256 and independently hashes every written file. A separate Python audit reconstructs every written file's Git blob identity, compares the exact original NUL-delimited Git tree inventories and checks all nine original symlink blobs. The portfolio contains 53,076,006 admitted original bytes. Every regular file in these heads was materialized; the nine symlinks were never created or followed.

One fresh observation holds one isolated tree. A future history qualifier can analyze and retire that tree before the next revision. Defaults admit at most 8 MiB per blob, 512 MiB of cumulative original bytes and 100,000 tree entries. The API accepts explicitly reviewed limits and additional protected repository roots. These limits govern materialization input, not analyzer AST/semantic/WASM allocation or physical RSS.

Symlinks, gitlinks, LFS pointers, unsupported path bytes, unsafe or nonportable paths, portable filesystem alias collisions and size-limit exclusions remain named inventory entries. Admitted symlink and LFS pointer bytes are hashed before skipping. Skipped size or path entries cannot claim complete original-blob verification. Failed originals produce a failure receipt; a successful materialization with skips never claims every regular file was written. Executable Git modes preserve their original bytes as ordinary, non-executable source files.

node scripts/materialize-production-history.mjs \
  --repository flask \
  --commit d086db856be187255b8ec61ef409357393020f32 \
  --source examples/flask \
  --output test-results/production-materialization-flask-RUN-ID

--corpus FILE selects a reviewed alternative corpus. The repository and full commit must belong to that corpus. Choose a fresh output directory outside the source repository; existing directories and paths through symlink aliases into the target are refused. Open its index.html in a browser. receipt.json and revision.json retain the exact observation; tree/ contains the isolated regular-file originals.

The original worktree, index and refs supply no source bytes. Git replacement objects, inherited Git overrides, global/system configuration and filesystem monitoring are disabled. No checkout, filter, submodule, LFS hydration, target dependency, application, hook, runtime, compiler or build executes. The separate analyzer and packaged-runtime qualification uses only Codiluce's owned Node/parser code.
