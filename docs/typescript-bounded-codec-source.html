The default transfer boundary

Previously the parent called V8 serialize on the complete request and checked its length afterward. The documented API returns a completed buffer and exposes no caller-supplied allocation cap. The implementation now uses private protocol 3 and a bounded binary writer. Pinned official Node 22 V8 API · Node 24 API.

All output blocks together allocate at most 64 MiB; final concatenation adds at most 64 MiB. String/binary payload bytes are admitted before chunk copying. Exact Latin-1 and UTF-16 code units, undefined properties, sparse arrays, maps/sets, cyclic/shared object references, supported native values and ordered proofs survive. String interning changes the private representation and expands every value exactly. The parent still uses Node’s IPC machinery to transfer the bounded Buffer.

The default child uses the same bounded encoding for its result. Smaller owned test budgets apply to its actual encoder, while production remains fixed at 64 MiB. No semantic producer version, source admission, parser deadline, compiler heap flag or external graph schema changes. Explicit alternate-worker fault probes retain their legacy V8 transport and do not qualify this default boundary.

Scope: this caps encoding buffers. Existing graph/project construction, traversal key arrays, reference tables, decoded graph ownership, BigInt text temporaries, direct in-process consumers, native/WASM allocation and total RSS remain separate budgets. It does not claim a 64 MiB parent heap or process-tree RSS limit.

Actual boundary and fidelity controls

Malformed/truncated frames and unsupported values fail explicitly.
