The small sample is the existing Next/Laravel integration fixture. Medium and large samples contain 250/1500 TS modules plus as many PHP controllers, indexed local calls, HTTP requests and registered API routes. Cold indexing starts with no parser/graph cache. Warm replay follows a cache-population pass in the same process. Peak memory is the parent process's Linux /proc VmHWM since exec (kernel RSS accounting can be approximate) at the end of cold indexing; it does not include concurrent parser child memory.

Warm replay cost: validating original sources and loading qualified native syntax units before Laravel application-cache replay increases warm medians by 13.5%/36.7%/27.9% on the small/medium/large samples. The existing 10% guard covers cold indexing and parent process-image peak memory; it does not certify warm replay or concurrent worker RSS. Lazy cache loading and full process-tree/history memory remain P10d qualification work.

Synthetic module depth and framework features are bounded; production repositories can behave differently.
